AIが書いたコードを受け取る

AIが書いたコードには出やすい欠陥の型があるので、依存の追加とテストの書き換えを中心に、人が確かめてから取り込む

出やすい欠陥分かっていること防ぎ方
存在しないパッケージを使うAIが書いたコードに出てくる架空のパッケージ名の割合は、
商用のモデルで少なくとも5.2%、
公開されたモデルで21.7%だった		依存の追加は人が承認する。lockfile の差分をレビューで見る
エラー処理が抜けるオープンソースの470件の PR の分析では、
AI が関わった PR は、エラー処理の抜けがほぼ2倍だった		エラーの状態を型で表す。AI に境界値分析を指示する
テストを弱めて CI を通す落ちるテストの期待値を書き換える、skip する、消す、
といった変更で CI を通そうとすることがある		アサーションの変更は、実装の変更と別に確かめる。
skip・削除されたテストの数を見える化する

依存の追加とテストの書き換えは、人が確かめる。レビューでは、差分を小さく保ち、境界・エラー処理・認可を毎回の観点にする

用語：依存＝自分のコードが使っている外部のパッケージ。lockfile＝インストールする依存の版を固定したファイル。アサーション＝テストの中で結果を確かめる1行（expect など）。skip＝テストを一時的に実行しないようにすること

注：2行目の分析は、AIレビューを提供する企業によるもの。倍率そのものより「どこが抜けやすいか」の傾向として使う

出所：Spracklen ら, USENIX Security 2025。CodeRabbit「State of AI vs Human Code Generation」
