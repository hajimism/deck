期待値の決め方

実装を見て逆算した期待値は実装の誤りをそのまま写すので、期待値は、仕様や受け入れ基準から、実装と独立に決める

期待値
テストで「こうなるはず」と書く、正しい結果
オラクル
テストの結果が正しいかを判定するよりどころ。仕様や受け入れ基準のほか、前の版の結果や「クラッシュしないこと」もよりどころになる

仕様

税込金額 ＝ 税抜金額 × 1.10（税率10%）

ところが実装は、誤って price * 1.08 と書かれている

実装を見て、期待値を逆算したテスト

// 実装を読むと 1.08 倍しているので…
expect(withTax(1000)).toBe(1080);

✓ 通る

テストは通るが、欠陥も一緒に固定される。
これはオラクルではなく、いまの実装の記録にすぎない

仕様から、期待値を決めたテスト

// 仕様では税率10%なので
expect(withTax(1000)).toBe(1100);

✕ 落ちる

テストが落ちて、欠陥が見つかる。
期待値が実装から独立しているから、実装の誤りに気づける

期待値が実装から独立していれば、テストが落ちたときに、実装の誤りに気づける

用語：回帰テスト＝変更によって既存の動きが壊れていないかを確かめるテスト

出所：Barr ら, “The Oracle Problem in Software Testing: A Survey”, IEEE TSE 41(5), 2015
