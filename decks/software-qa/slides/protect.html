品質特性

保証する品質は機能だけではないので、9つの品質特性ごとに起きうる問題を洗い出し、それぞれに確かめ方を用意する

ISO/IEC 25010
ソフトウェアの品質を、性質ごとに分けて定義した国際規格。分けた1つ1つを品質特性と呼ぶ

  • 機能適合性自動テストの多くが確かめる特性

    計算結果、バリデーション、画面遷移

    確かめる手段ユニット・コンポーネント・E2Eテスト

  • 性能効率性

    Core Web Vitals、バンドルサイズ

    確かめる手段Lighthouse CI、利用者環境での計測

  • 互換性

    ブラウザの違い、APIスキーマとの整合

    確かめる手段複数ブラウザでの実行、契約テスト

  • 相互作用性

    使いやすさ、アクセシビリティ、エラー文言

    確かめる手段axe の自動監査、キーボードでの確認

  • 信頼性

    オフライン時の挙動、エラー境界、リトライ

    確かめる手段エラー状態のテスト、本番の監視

  • セキュリティ

    XSS、認可の漏れ、トークンの扱い

    確かめる手段依存の検査、セキュリティテスト

  • 保守性

    モジュール性、テストのしやすさ

    確かめる手段型・lint、レビュー

  • 柔軟性

    画面サイズ、多言語対応

    確かめる手段画面サイズ・言語ごとの見た目の確認

  • 安全性

    二重決済の防止、危険な操作の確認

    確かめる手段二重送信や確認ダイアログのテスト

自動テストの多くは機能適合性の確認にとどまる。ほかの特性には、計測や監査など別の確かめ方を用意する

用語：Core Web Vitals＝表示の速さ・操作への反応・見た目の安定を測る指標。Lighthouse CI＝ページの速さなどを自動で計測する仕組み。axe＝アクセシビリティの違反を自動で検出する道具。XSS＝悪意のあるスクリプトを画面に埋め込まれる脆弱性。認可＝誰に何をさせてよいかの判定

注：2023年版で8特性から9特性になった。改称（使用性→相互作用性、移植性→柔軟性）と安全性の追加は、規格本文が有料のため二次の解説による
